# Retrieval contract v1

Inputs are exact frozen dataclasses and exact immutable tuples. Fail with ValueError instead of coercing wrong values. Complete chunk keys contain tenant, document, revision and ordinal. Character offsets are Python string indices, with exact original slice text and SHA256 of its UTF-8 bytes. The digest checks identity/integrity, not authority. Do not strip whitespace. A changed revision changes the key. Consistent revision/ACL metadata and a complete current corpus are supplied application assumptions, not a durable store guarantee.

`make_chunks`: revalidate the Document, width 16..512 characters, overlap 0..width-1, at most 32 windows. Advance start=end-overlap; stop when end reaches source length, without emitting another overlapping tail. Exceeding the cap fails the whole call. Documents are nonblank and at most 8192 UTF-8 bytes. Windows preserve whitespace and contain at most 2048 bytes.

`retrieve`: k is an exact integer 1..10; mode cosine or lexical. Corpus is an exact tuple of at most 64 distinct complete chunk keys with one coherent Spec equal to the query. Validate model ID, version, dimensions 1..32; every vector has the stated length, finite exact int/float coordinates (no bool), magnitude at most 1,000,000 and Euclidean norm at least 1e-12. Bad data anywhere fails, including excluded rows. This bounded in-memory validation is not a physical time/memory isolation guarantee.

Determine the latest revision for each (tenant, document) across the corpus BEFORE filtering. Older public rows must not return when the current revision is restricted, inactive or removed by metadata filters. Then retain only the application-supplied principal's tenant, active rows, public rows or rows with at least one allowed group, and matching optional topic/document filters. Only eligible rows may be scored. Take top k AFTER filtering. The principal is trusted application input; query or document text never grants access. Authentication, atomic reindexing, deletion/tombstones and a complete production authorization system are outside this lab.

Cosine uses normalized dot product (math.hypot and math.fsum); clamp rounding to [-1,1]. Negative similarity is meaningful. A score is not a probability or a truth guarantee. Lexical mode uses lowercase ASCII alphanumeric token SET Jaccard, returning zero for an empty union. It is not BM25, hybrid search or a linguistic tokenizer. Apply an optional inclusive min_score in [-1,1] after scoring. Thresholds have mode-specific meaning. Sort by descending score, then ascending complete Key. Hits return key/offsets/digest/score, no text, vectors or ACL fields. No ANN or database index is implemented.

`evaluate`: at most 32 exact cases with distinct IDs; at most 16 distinct complete relevance keys per case. Labels must name eligible, active, latest chunks under the case's tenant/groups/metadata, BEFORE score threshold. Reject missing, old, inactive or inaccessible judgments. Run actual retrieval rather than accepting supplied hits. Precision@k = matched/k, using REQUESTED k, so missing result slots contribute zero. Recall = matched/number of relevant labels. Reciprocal rank = 1/rank of first relevant hit, or zero if missed. Average precision across ALL cases, recall and reciprocal rank across ONLY cases with positive labels. No-label cases have null recall/rank; report their case count and unwanted returned hits separately. An empty case set returns null averages, not a perfect score, and makes no corpus-quality claim.

The packaged JSON is bounded to 65536 bytes, exact fields, UTF-8, no duplicate keys/non-finite constants, at most 16 document revisions and 16 queries. Width=96/overlap=24, hand-assigned six-dimensional fixture-v1 vectors and full chunk judgments are pinned. These are original complete judgments ONLY for this tiny development fixture, not held-out model evaluation. There are 12 revisions, 15 chunks, nine queries, seven positive-label cases and two no-label cases. Compare the same data at k=1/3 in cosine/lexical modes; do not infer that tuned scores generalize.

Source and installed tests cover 83 finite cases. They do not prove an embedding model is accurate, all future data is secure, retrieval implies answer correctness, or learner mastery. Later RAG must decide whether returned evidence supports an answer and how to cite or abstain.

Primary reading: [ranked retrieval evaluation](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html), [math.hypot](https://docs.python.org/3.13/library/math.html#math.hypot), [pgvector](https://github.com/pgvector/pgvector) for planned database indexing, not this implementation.

# SQL query analysis lab

Finish three SQL resources: summary.sql, history.sql and search.sql. Their wrappers, strict values, read-only ownership and two fixed EXPLAIN queries are supplied. Public cases describe outputs independently of a particular SQL spelling. Use Python 3.13+ and the eight completed previous wheels; then install this package with `python -m pip install -e '.[dev]'`. Never connect this rehearsal to production or the academy database.

Run `python -m pytest -q`. Live cases require private ACADEMY_QUERY_DSN naming a disposable PostgreSQL database. Missing configuration explicitly skips store cases; that is not PostgreSQL evidence. The supplied store helper creates one service schema through delivery_004 and a separate reporting schema with query_note's complete foreign key to service facts. Its query engine has report,source search_path; credentials are caller-owned. Each read borrows the engine and owns a fresh read-only READ COMMITTED transaction with local 250ms lock/1000ms statement limits. The engine stays caller-owned. Result limits bound returned rows, not all scanned work or total elapsed time.

summary.sql must left-join existing sources, all their revisions and a complete-key grouped note relation. Several notes must not multiply totals; count(r.id) and coalesced sums distinguish empty sources from absent ones. history.sql computes LAG, delta, an explicit ROWS running total and a newest flag over all scoped revisions before ascending output LIMIT. search.sql ranks newest revisions before matching note JSONB through complete-key EXISTS. Matching an old note must not resurrect an old revision; sort by value descending then C-collated id/revision. Bind scope, JSON and limits; never interpolate values.

Filter accepts only a bounded object containing kind/region with null or printable strings. JSON null, missing key and empty string have different meaning. The schema uses primary/foreign keys for stable identity; JSONB holds optional metadata. Authorization belongs to the application before this library; a namespace argument is not authentication.

Run `python demo.py --output queries.json` against the disposable store. A deterministic 40,000-record/note workload has 100 selective high values and ten rare notes. The experiment ANALYZEs, saves baseline EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON), explicitly creates a namespace/value/id/revision B-tree and body jsonb_path_ops GIN, then saves selective and wide observations. It checks identical ordered results, drops the fixture indexes and checks original source migration metadata again. This is local experimental DDL, not a new production migration. EXPLAIN ANALYZE executes SELECT; never pass arbitrary user SQL into it.

Read plans as observations: costs are planner units, not milliseconds; actual rows are per loop; parent/child buffer figures overlap and must not be summed. Planning/row statistics, warm caches, limits, write overhead, selectivity and order matter. The supplied plan summary keeps actual node estimates/rows/loops/index names, root buffers/cost and execution time. It never forces scans off or asserts a fixed plan, universal speedup or timing threshold. Add two useful regressions and an explanation before manual review. Four criteria and reported tests never award mastery.

# Local protocol and limits

GET `/v1/namespaces/{namespace}/snapshot?limit=16`: exact configured Bearer first; limit 1..32, no unknown/duplicate query fields. Canonical ASCII JSON includes version, namespace, limit, ordered id/revision/value items and next cursor. Strong ETag hashes exact bytes. If-None-Match allows a lone `*` or at most sixteen strong/weak quoted tags, <=1024 characters, commas inside quotes and space/tab separators. Empty list elements/malformed/trailing/mixed wildcard are rejected by this lab policy. Matching GET returns bodyless 304. Both success statuses send `private, no-cache`, `Vary: Authorization` and ETag. Errors have no ETag and use no-store. Each validation still reads current PostgreSQL rows; this is transfer caching, not an in-memory query cache. Only GET conditional validation is supplied; this is not a general HEAD/update precondition implementation.

POST `/v1/namespaces/{namespace}/webhooks`: exact single X-Delivery-ID, X-Signed-At, X-Signature; application/json and identity encoding; streamed bytes 1..4096. Signing secret is selected by configured route. Signature is `v1=` plus 64 lowercase hex HMAC-SHA256 characters. Message: ASCII `academy-webhook-v1\n{namespace}\n{delivery_id}\n{timestamp}\n` followed by original raw bytes. Namespace and delivery match `[a-z][a-z0-9-]{0,31}`; timestamp is nonzero decimal <=10 digits. Supplied positive integer epoch clock allows +/-300 seconds inclusive. This is an academy-specific protocol, not a provider-compatible wire format. Compare fixed-format digests with hmac.compare_digest; never parse/reserialize before verification.

Authenticated JSON has exactly integer version 1, id, exact integer revision 1..8 and exact integer value 0..1000000. No duplicate keys, body tenant, extra fields, booleans, floats or coercion. Receipt key is namespace/delivery; stored digest hashes raw body, excluding timestamp/signature. Retry stable bytes and ID with a fresh signature. Same digest returns duplicate true. Changed bytes under the identity conflict even when JSON meaning is equal. New delivery/equal existing reading commits a new receipt without a second fact. A different existing reading rolls its new receipt back. Source insertion, receipt and reading share one READ COMMITTED transaction with individual 250ms lock/1000ms statement limits. Respond after commit; no automatic retries or implicit outbox enqueue.

Statuses: missing/invalid Bearer 401 (Bearer challenge), wrong namespace 403; bad snapshot query 422 and conditional header 400 after permission. Webhook auth/freshness/scope failure 401; media/encoding 415; oversize 413; authenticated invalid event 422; delivery/reading conflict 409; expected storage/pool error 503 generic. Webhook/errors no-store. Trace logs contain generated ID/status only. A 503 or lost reply can conceal commit: reconcile stable delivery identity. 409 needs a semantic decision, not blind new IDs.

Parent /ready checks delivery_004 source shape and receipt-table columns; old standalone /ready remains 503 at that head. Readiness is a scoped observation, not full constraint/data audit, authorization or admission guarantee. Original service paths are mounted unchanged. Explicit disposable setup/teardown owns receipt DDL; no production migration/receipt retention/delete/rotation mechanism is supplied. Removing receipt history loses delivery deduplication. Key holders can authenticate messages, so signature is not external nonrepudiation. TLS/proxy/body-header total-memory limits, hostile clients, rate limits, hard deadlines and public deployment remain unverified. Local receipt/fact atomicity does not provide external exactly-once effects or expert certification.

References: [HTTP conditional semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2), [HTTP cache directives](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2), [Python HMAC](https://docs.python.org/3.13/library/hmac.html), [provider raw-byte example](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries).

# ADR 0033: scoped query analysis and observed plans

Date: 2026-10-07. Status: accepted.

The connected backend path needs joins, windows, JSONB and actual query-plan evidence. A finished delivery/service chain alone does not teach correct reporting or establish index benefits. We preserve that source contract and add a bounded local SQL project.

Use a separately installed extension depending on the completed release package. Three labelled unfinished SQL resources produce independent reports; typed wrappers, strict copied filters, read-only transaction ownership and closed SELECT plan observations are supplied. Complete-key grouping prevents note fanout; left joins distinguish empty and absent sources. Window LAG/delta/explicit ROWS/newest calculations precede output limits. Newest revision selection precedes complete-key EXISTS/JSONB containment, preserving null/missing/empty and deterministic equal-value ordering. Application permission precedes the library's namespace argument.

Caller-owned PostgreSQL/psycopg2 engines remain borrowed. Each read owns a fresh non-autocommit READ COMMITTED transaction with read-only mode and individual lock/statement limits, then materializes copies/releases its connection. Limits bound returned rows and individual statements, not all scan work or hard total elapsed time; separate calls have separate snapshots. No import/read-time migrations/index work or new HTTP endpoint.

The trusted fixture creates a separate reporting schema whose notes reference full keys in the unchanged delivery_004 source schema. Explicit experimental B-tree(namespace,value,id,revision) and JSONB jsonb_path_ops GIN indexes are dropped before source migration comparison. Existing source facts and metadata stay unchanged after cleanup. This local DDL is not a new service migration or concurrent production index rollout.

The deterministic workload has 40,000 facts/notes, 100 selective high values and ten rare notes. ANALYZE precedes actual EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) observations. Save baseline, selective indexed and wide-range plans and check identical ordered results. Preserve node estimates/actual rows/loops/index names, root buffer totals/cost and execution time. Costs are not milliseconds; root/child buffers overlap; LIMIT/statistics/cache state and index write/storage overhead matter. Do not force scans off, promise universal speedup or gate on exact plans/machine-specific timings. The original observed run chose the candidate B-tree and GIN; that is finite evidence, not a guarantee.

Five simple lessons/ten scenarios plus complete guided/diagram/glossary/private recall layers link to an authenticated nineteen-file starter, 36 public cases (23 offline/13 PostgreSQL) and four manual criteria. Nine real source/wheel packages are freshly installed outside source; resources/types/imports, store cases, all five literal lesson SQL examples, report readback/source compatibility and owned cleanup are verified. The academy serves bytes/stores reported or manual evidence only. No learner SQL execution, old exam/runner/academy schema/dependency change or expertise certification.

Alternatives: using Python-only simulations would not evaluate PostgreSQL; joining note rows directly can silently multiply facts; SUM(DISTINCT value) erases legitimate equal facts; filtering metadata before ranking changes newest semantics; head/index names alone do not validate query results; exact timing/plan assertions create machine-dependent grades. We use independent output contracts and honest observed plans.

Primary references: [table expressions](https://www.postgresql.org/docs/17/queries-table-expressions.html), [window functions](https://www.postgresql.org/docs/17/tutorial-window.html), [JSONB](https://www.postgresql.org/docs/17/datatype-json.html), [EXPLAIN](https://www.postgresql.org/docs/17/using-explain.html). Actual pinned PostgreSQL 17.11 tests determine the local evidence scope.

# Step seven — portfolio work and comprehensive assessment

Agreed scope from PROJECT_BRIEF sections 29 and 34; started 2026-10-12.
The academy supplies the learning experience. Learners build and defend their own portfolio products; downloading a pack does not mean those products exist or meet production requirements.

Acceptance checklist (check only after verification):

- [x] Three complete portfolio build packs: backend commerce, enterprise RAG and multilingual finance. Each has requirements, ordered milestones, failure cases, evidence templates, acceptance matrix, learning links and a review rubric. Existing milestone IDs and submission history survive.
- [x] Original engineering knowledge exam, approximately 150 minutes: single choice, multiple response, code/database/HTTP/distributed/AI/security reasoning and short written answers. Category scores exclude written judgment; reference answers stay private until submission.
- [x] Practical repair exam, approximately 300 minutes: downloadable deliberately broken application, public regressions, additional private Docker checks, saved source and immutable execution evidence. Deployment, architecture and operational claims require manual review. No learner source executes in the academy API.
- [x] Senior design exam, approximately 240 minutes: multi-tenant enterprise assistant, baseline artifacts, seven staged incidents, explicit senior rubric and saved responses. Committed earlier stages remain fixed; judgments are attributable self/human review.
- [x] Resumable per-account attempts; question flags, saved position, elapsed study timer, strict answer validation, atomic/idempotent submission and frozen content. Timers are advisory, not proctoring or forced expiry.
- [x] Submitted written/repair/design evidence connects to the existing invited-review and revision workflow. No fabricated manual score, mastery, readiness percentage or identity guarantee.
- [x] API, isolation, browser/mobile, migration and production build checks; preserve all previous content definitions and learner evidence. Record actual commands/results and limitations.

Stop after verified step seven. Step eight is everyday reliability: Docker/PostgreSQL deployment, backup/restore, recovery, exports, accessibility and mobile acceptance.
